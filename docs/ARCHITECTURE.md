# Model and operational contract / 模型与运行约定

Manifest JSON has only `steps` and nonempty object `target`. Each step has `id`, optional unique `requires`, optional JSON object `payload`. IDs are ASCII `[A-Za-z0-9_.-]{1,80}`. There are 1..64 ordered steps; prerequisites must already appear. Cycles, forward edges and missing references are rejected, not silently reordered. Keeping a step requires keeping all declared prerequisites. A candidate is an ordered subsequence; no payload editing or new prerequisite insertion. The empty subsequence is permitted.

候选空间是原步骤顺序下的依赖闭合子集，保留步骤必须保留其所有前置步骤。删除一个步骤时，local 模式同时删除它的所有依赖步骤；不是通过添加前置步骤来“修复”候选。输入清单保持不变；报告含缩减清单。未声明的运行状态与依赖不在保证范围内。

Exact enumerates every subset and checks all dependency-closed candidates, without a monotonicity assumption. It reports `CARDINALITY_MINIMUM_AND_INCLUSION_MINIMAL` only after full enumeration with every oracle query determinate. This implies no permitted proper subset of the selected target reproducer is target-failing under the recorded deterministic observation predicate. `alternatives` includes every observed equal-cardinality minimum; a single deterministic choice does not imply uniqueness. Unknown observations anywhere conservatively block exact completion. Local greedily removes a step plus dependents; completion certifies only the final tested dependent deletions. It does not certify arbitrary multi-step deletion or global/inclusion minimum. The nonmonotone contrast demonstrates the gap.

`TARGET` is structured signature equality after canonical JSON serialization; `PASS` is protocol success; `OTHER` is a different structured failure; `INVALID` is setup failure; `TIMEOUT` is exceeded wall clock; `ERROR` includes launch/protocol/output failures. Contradictory accumulated repeated observations are `INCONSISTENT`. Incomplete repeat budgets are aggregate `UNKNOWN`. Only TARGET permits a reduction. PASS and OTHER are determinate non-targets; INVALID, TIMEOUT, ERROR, INCONSISTENT and UNKNOWN block proof. No majority vote, no statistical flake-absence claim. Two repetitions cost twice the invocations and may still miss rare flakes.

缓存键绑定候选内容与顺序、目标签名、重复策略、oracle/配置身份及声明的环境身份。`Evaluation.fresh_calls=0` 明确表示缓存观测；`refresh=True` 追加观测，不覆盖旧记录。改变 identity 会使用不同键。缓存只在一个 EvidenceOracle 内存对象中存在，默认 CLI 不跨运行复用。声明之外的网络、数据库、系统时间等变化可能造成未观测的不稳定，必须由调用方管理。

Runner JSON:

```json
{
  "command": ["/absolute/path/python", "/absolute/path/oracle.py", "release", "{candidate}"],
  "cwd": "/absolute/existing/work-directory",
  "env": {},
  "environment_identity": {"fixture": "v1"},
  "code_inputs": ["/absolute/path/oracle.py"],
  "timeout_ms": 5000,
  "max_output": 65536
}
```

One whole argv element is replaced with the temporary candidate JSON path. No shell runs. Candidate JSON is `{"steps": [...]}`. The runner receives exactly the provided environment mapping; no environment inheritance. Windows normally needs explicit `SystemRoot`/`WINDIR`, generated by the demo. Absolute executable, existing cwd and explicit environment identity are required. Executable and declared code-input bytes are rehashed at evaluation time; declare all invoked script/config files in `code_inputs`. Python executable hash alone cannot identify imported modules. Cwd paths, command paths and env values bind cache privately; reports expose only key hashes. Reports intentionally retain payloads and signatures needed to reproduce, so users must sanitize them before sharing.

Oracle stdout must be exactly one UTF-8 JSON object: `{"status":"PASS"}` with exit 0; `{"status":"INVALID"}` with nonzero exit; or `{"status":"FAIL","signature":{...}}` with nonzero exit. Unknown keys/status, absent signature, inconsistent exit, malformed/duplicate-key JSON or resource failure become ERROR. Combined stdout/stderr byte budget counts actual bytes; output contents are not copied into public error details. Timeout/output excess terminates supported process trees. On Windows a suspended process is placed in a kill-on-close Job before resuming. On POSIX a new session/process group is killed. Windows descendants remain in the Job; POSIX daemonizing descendants which create another session/process group are unsupported. Commands are trusted, explicitly chosen local programs, not security-contained untrusted code.

Limits: JSON input/canonical value <=1 MiB, nesting <=32, finite numbers, integers within ±(2^53−1); repetitions 1..100; actual calls 1..1,000,000; inspected subset states 1..1,000,000; timeout 1..3,600,000 ms; output 128..1,048,576 bytes. Bool is never accepted as an integer control. The same JSON limits apply to report serialization; very large transcripts may require smaller bounds. Input/output resolved aliases and existing destinations are rejected before any oracle execution. New report creation uses exclusive mode; no silent overwrite.

Complexity: exact examines O(2^n) subset states and up to O(r·2^n) invocations; dependency validation O(n+e) per subset; records require O(c·r·payload size) memory within the finite call/state bounds, not an arbitrary workload guarantee. Local has at most n successful deletions and O(n²) tested dependent deletions, each O(n+e), absent cache savings. Runner identity hashing costs total declared executable/code bytes per evaluation, so large binaries can dominate fast oracles. Resource bounds return an incumbent target observed so far plus UNKNOWN, never an untested minimum. Calling code must isolate/reset its application state between invocations.
